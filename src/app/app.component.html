Rows backed by an API

The same outputs wired to a REST endpoint instead of a local array — edits POST, deletes DELETE after the grid's own confirm prompt. Localised here with lang="zh-CN" to show the bundled translations.

treeChildrenKey="children" — each row's nested children array is its subtree. Click ▸ to expand. Filtering keeps a branch when the node or a descendant matches, and opens the path to it; sorting orders each sibling level independently.

Pinned rows

[pinnedTopRows] keeps a highlighted account above the scroll body and [pinnedBottomRows] a totals row below it. Neither is part of data(), so sorting, filtering and paging leave them alone.

5,000 rows with virtualScroll="true" — only the rows in the viewport exist in the DOM, no pagination. Sorting by Price still orders all 5,000, and grouping keeps working while virtualized.

One theme attribute. Every theme is a plain CSS custom-property set, so a fourth one is a stylesheet away.

What you get

Every one of these ships in the MIT package. There is no second package to buy.

Sorting & filtering

Click to sort, shift-click for multi-column. One free-text box across every column, plus type-aware per-column filters — text, number range, date range, boolean.

Row grouping & aggregates

Drag a header into the group bar. sum, avg, min, max and count per column, with a totals row.

Tree data

Nested children arrays render as an expandable hierarchy, with filtering and sorting that understand the tree.

Virtual scroll

Thousands of rows without pagination — only the viewport is in the DOM, via @angular/cdk. Infinite scroll is a flag away.

Inline editing

Per-column editable, with required / min / max / pattern and async validators checked at save time. Create and delete rows too.

Export

CSV, Excel and PDF from the toolbar. jspdf is lazy-loaded, so you only pay for the PDF path if someone uses it.

Selection & cell ranges

Checkbox row selection, drag-select cell ranges, Ctrl-drag for several rectangles at once, and clipboard paste events.

Columns, your way

Resize, reorder, pin left or right, show/hide, and double-click a handle to autosize. Custom cell and header templates when the defaults aren't enough.

i18n & theming

English, Spanish, French, Italian and Chinese bundled; override any string. Three themes built on CSS custom properties.

Why another grid?

Because the genuinely useful parts — grouping, Excel export, range selection, aggregation — are usually the ones behind an enterprise licence.

Server-side, without writing the server half

Put the grid in serverSide mode and it stops sorting, filtering and paging locally — it emits what the user asked for and waits for your data. Wire that to any backend, or drop in the official .NET companion and skip the plumbing.
